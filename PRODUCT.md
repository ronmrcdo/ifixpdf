# iFixPDF

A desktop PDF workspace (Windows, macOS, Linux) using Tauri 2 + Rust. The preferred browser prototype is a compact blue-grey desktop shell with Home, Merge PDFs, read-only Preview PDF, Edit PDF and Settings. IBM Plex Sans, Lucide controls and the folded-F iFixPDF logo define the interface. The frontend is React 19 + TypeScript (strict) on Vite.

Working frontend features include PDF.js preview, pdf-lib merge/export, page reorder/rotation, multi-selection, duplicate/delete/extract, session undo/redo, IndexedDB recents/drafts, Home document actions, AES-256 protected-copy export and range/every-page Split to ZIP. Home opens Preview; Edit owns mutations and its save inspector. Merge has Add → Arrange → Save → Done stages. Print Jobs and This Session / Project Pack were explicitly removed.

Fill, Sign and Redact are implemented in Edit's Document tab (browser-verified; Windows pending): add text, check, cross and dot marks; fill existing form fields; draw or import a signature (remembered on this device in IndexedDB only when the user ticks Remember; off by default), place, move and resize it; and redact areas. Every export (Save as, Extract, Split ZIP, Preview Save a copy, Print) includes them. Saved copies are flattened: fills and items are drawn into the page, and each page with a redaction is replaced by an image of that page so nothing of the covered content remains. Preview shows them read-only. Until the document is closed, its draft keeps the placed items, signature images included, and the filled values, whether or not the signature was remembered.

Installed-PC updates (manual check, Settings → About) and native file saves (Rust `save_as` command) are implemented and verified in the browser only. Compression in Edit/Merge save settings is planned in IMPLEMENTATION.md and not implemented. Windows build/installer verification and signing remain pending. Rust supplies the shell and Save as (the `save_as` command: native save dialog plus atomic write); there is no shipped Windows executable. Manual PDF-viewer printing is available.

The app ships no sample documents and starts with an empty workspace. Browser PDF bytes are stored locally in origin-scoped IndexedDB; production should use an explicitly designed native document repository and retention policy.
